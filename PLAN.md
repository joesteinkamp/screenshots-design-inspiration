# Plan: MCP Server for Screenshots Design Inspiration

## Context

AI models lack access to curated, real product screenshots — the training corpus is vast but unfocused, and product UI screenshots are often missing or outdated. This repo contains **227 Web, 178 Mobile, and 4 Email** product screenshot galleries with rich tag metadata. Turning it into an MCP server lets AI tools query this library directly — getting actual images and structured metadata for UI design inspiration with defined scope.

## Approach: GitHub Pages as Data Source (Option C)

The Jekyll build generates a static `products.json` index on GitHub Pages. The MCP server is a lightweight client that fetches this index and serves images via GitHub Pages URLs — no need to clone 2.7GB of images locally.

```
┌─────────────────────────────────────────────────┐
│  GitHub Pages (static hosting)                  │
│                                                 │
│  /api/products.json  ← new, generated by Jekyll │
│  /Web/Airbnb/*.png   ← existing images          │
│  /Mobile/Slack/*.png ← existing images           │
└──────────────┬──────────────────────────────────┘
               │ fetch index + images over HTTPS
┌──────────────▼──────────────────────────────────┐
│  MCP Server (TypeScript, stdio)                 │
│                                                 │
│  - Fetches products.json at startup             │
│  - Queries in-memory index                      │
│  - Fetches images from GitHub Pages on demand   │
│  - Returns base64 image content via MCP         │
│  - Runs locally OR can be deployed remotely     │
└─────────────────────────────────────────────────┘
```

## Part 1: Jekyll Plugin — Generate `products.json`

### New file: `_plugins/products_json.rb`

A Jekyll Generator plugin that runs at build time and produces `/api/products.json` containing all product metadata and image URLs. Mirrors the logic in `_plugins/product_list.rb` but outputs a complete JSON file.

**Output format:**

```json
{
  "generated_at": "2026-04-02T...",
  "base_url": "https://joesteinkamp.github.io/screenshots-design-inspiration",
  "products": [
    {
      "name": "Airbnb",
      "platform": "Web",
      "path": "Web/Airbnb",
      "tags": ["Feedback", "Survey", "Minimalist", "Light Mode"],
      "images": [
        "Web/Airbnb/Screen Shot 2020-05-25 at 10.05.56 PM.png",
        "Web/Airbnb/Screen Shot 2020-05-25 at 10.06.01 PM.png"
      ],
      "image_count": 38,
      "gallery_url": "/Web/Airbnb/"
    }
  ],
  "tags": {
    "Minimalist": 45,
    "Dark Mode": 32,
    "SaaS Dashboard": 28
  }
}
```

**Key details:**
- Scans `Web/`, `Mobile/`, `Email/` directories (same as existing `product_list.rb`)
- Parses frontmatter from each product's `index.html` to get `tags` and `gallery-directory`
- Lists ALL image files per product (not just first 4) with relative paths
- Includes a pre-computed tag frequency index
- Image URLs are relative paths — the MCP server prepends `base_url` to form full URLs
- URL-encodes image paths (filenames contain spaces)

**Files to modify:**
- Create `_plugins/products_json.rb`
- Create `api/` directory with a placeholder (Jekyll needs it, or the plugin writes directly)

## Part 2: MCP Server

### Structure

```
mcp-server/
  package.json
  tsconfig.json
  src/
    index.ts          # Entry point, server setup, stdio transport
    data.ts           # Fetch + cache products.json, in-memory index
    tools.ts          # MCP tool definitions + handlers
    types.ts          # TypeScript interfaces
```

**Dependencies:** `@modelcontextprotocol/sdk`, `zod`

No `sharp` or `gray-matter` needed — images come from GitHub Pages URLs (fetched as binary, base64-encoded), and metadata comes pre-parsed from `products.json`.

### Data Layer (`data.ts`)

- On startup, fetch `https://<site>/api/products.json`
- Build in-memory `Product[]` array and `Map<string, Product[]>` tag index
- Cache with a TTL (e.g., 1 hour) — refetch when stale
- All image URLs are constructed as `${base_url}/${encodeURI(imagePath)}`

### MCP Tools (`tools.ts`)

#### 1. `search_by_tags`
Find products matching design patterns (e.g., "dark mode dashboards").
- **Input:** `{ tags: string[], match?: "all" | "any" }`
- **Output:** Matching products with name, platform, tags, imageCount, galleryUrl
- Case-insensitive partial matching ("dark" matches "Dark Mode")

#### 2. `get_product_screenshots`
Return actual screenshot images for a specific product.
- **Input:** `{ product: string, platform?: string, limit?: number }`
- **Output:** Product metadata + MCP image content blocks (base64)
- Fetches images from GitHub Pages URLs, converts to base64
- Default limit: 4 images
- Images may be large — consider noting this in tool description so AI agents use judiciously

#### 3. `browse_by_platform`
List all products for a platform.
- **Input:** `{ platform: "Web" | "Mobile" | "Email", limit?: number, offset?: number }`
- **Output:** Paginated product list (metadata only, no images)

#### 4. `search_inspiration`
Free-text search across product names and tags.
- **Input:** `{ query: string, platform?: string }`
- **Output:** Ranked list of matching products
- Keyword extraction + matching against tags and product names

#### 5. `list_tags`
Discover what's available to search for.
- **Input:** `{ platform?: string }`
- **Output:** `{ tag: string, count: number }[]` sorted by frequency
- Pulled directly from the pre-computed `tags` object in `products.json`

#### 6. `get_random_inspiration`
Random sampling for creative exploration.
- **Input:** `{ count?: number, platform?: string, tags?: string[] }`
- **Output:** Random products with metadata (no images — use `get_product_screenshots` to fetch)

### Server Entry Point (`index.ts`)

- Create MCP server via `@modelcontextprotocol/sdk`
- Register all 6 tools
- Connect via `stdio` transport
- Fetch and index `products.json` on startup
- Configurable via env var: `SCREENSHOTS_BASE_URL` (defaults to the GitHub Pages URL)

### Distribution: npm Package

The MCP server is published to npm as `screenshots-design-inspiration-mcp` so anyone can use it with zero setup — no cloning, no building, no local images.

**`package.json` (key fields):**

```json
{
  "name": "screenshots-design-inspiration-mcp",
  "version": "1.0.0",
  "description": "MCP server for UI design inspiration from real product screenshots",
  "bin": {
    "screenshots-design-inspiration-mcp": "./dist/index.js"
  },
  "files": ["dist"],
  "scripts": {
    "build": "tsc",
    "start": "node dist/index.js",
    "prepublishOnly": "npm run build"
  }
}
```

The `bin` field is what makes `npx` work — it tells npm which file to execute. The `dist/index.js` file needs a `#!/usr/bin/env node` shebang at the top.

### User Setup

**Option A: Claude Code (one command)**

```bash
claude mcp add design-screenshots -- npx screenshots-design-inspiration-mcp
```

**Option B: Claude Desktop / Cursor / any MCP client (add to config JSON)**

```json
{
  "mcpServers": {
    "design-screenshots": {
      "command": "npx",
      "args": ["screenshots-design-inspiration-mcp"]
    }
  }
}
```

That's it. No repo clone, no install, no build. `npx` handles everything.

**Option C: Local development (for contributors)**


## Implementation Steps

### Step 1: Jekyll plugin for `products.json`
- Create `_plugins/products_json.rb`
- Reference `_plugins/product_list.rb` for directory scanning pattern
- Parse frontmatter from each product `index.html` for tags
- Output complete JSON with all products, all images, tag index
- Test locally with `bundle exec jekyll build` and verify `_site/api/products.json`

### Step 2: Scaffold MCP server
- Create `mcp-server/` with `package.json`, `tsconfig.json`
- Install deps: `@modelcontextprotocol/sdk`, `zod`
- Define types in `types.ts`

### Step 3: Data fetching layer
- `data.ts`: fetch `products.json` from GitHub Pages URL
- Build in-memory product and tag indexes
- Image URL construction with proper encoding for spaces in filenames

### Step 4: Implement tools
- `tools.ts`: all 6 tools with Zod input schemas
- `search_by_tags`: filter products by tag overlap
- `get_product_screenshots`: fetch images from GitHub Pages, base64 encode, return as MCP image content
- `browse_by_platform`: simple filter + pagination
- `search_inspiration`: keyword extraction + scoring
- `list_tags`: return pre-computed tag counts
- `get_random_inspiration`: random sampling with optional filters

### Step 5: Wire up server
- `index.ts`: create server, register tools, stdio transport
- Add `#!/usr/bin/env node` shebang to entry point
- Add build/start scripts to `package.json`
- Set `bin` field in `package.json` pointing to `dist/index.js`

### Step 6: Deploy Jekyll plugin
- Push Jekyll plugin change — GitHub Actions builds and deploys `products.json` to GitHub Pages
- Verify `products.json` is accessible at the GitHub Pages URL

### Step 7: Publish to npm
- Add `.gitignore` entries for `mcp-server/node_modules/` and `mcp-server/dist/`
- `npm login` and `npm publish` from `mcp-server/`
- Verify `npx screenshots-design-inspiration-mcp` starts the server
- Add setup instructions to repo README
